## Falhas reproduzidas e corrigidas

### Schema de imóveis

O código da vitrine, dos detalhes e do formulário utiliza `imoveis.descricao`, mas a coluna não existia no banco ativo. A consulta retornava PostgreSQL `42703` e `GET /api/imoveis` respondia HTTP 500.

A migration `20261020215455_add_imoveis_descricao.sql` adiciona a coluna opcional sem modificar registros existentes. Depois da aplicação, listagem, detalhe, cadastro e edição com descrição responderam corretamente.

### Permissões antigas do Storage

O banco continha políticas do editor visual chamadas `Permitir Uploads 11dunwl_1`, `_2` e `_3`, concedendo INSERT, UPDATE e DELETE para `public` no bucket `imoveis_imagens`. Um upload direto com a chave anônima foi aceito durante a reprodução. O objeto criado para esse diagnóstico foi removido.

A migration `20261020215459_restrict_legacy_imoveis_storage_writes.sql` remove somente essas três políticas. A política SELECT e o bucket público foram preservados. Depois da aplicação:

- Uploads PNG, JPEG e WebP autorizados pela API e enviados com token assinado funcionaram.
- Os arquivos públicos baixados eram idênticos aos bytes enviados.
- Upload anônimo sem token e alteração anônima foram recusados.
- A tentativa de exclusão anônima não removeu a imagem de teste.

As duas migrations foram executadas pelo SQL Editor no Chrome, no projeto conferido, dentro de uma transação. O resultado confirmou `descricao_disponivel = true` e `politicas_inseguras_restantes = 0`. Não foi reaplicada a migration inicial. O projeto não possuía `supabase_migrations.schema_migrations`: esta execução foi manual e não representa uma sincronização do histórico do CLI.

### Acesso local por 127.0.0.1

O ajuste de `next.config.ts` permite `127.0.0.1` em `allowedDevOrigins`. Recursos JavaScript de desenvolvimento passaram de HTTP 403 para 200 nesse endereço, mantendo o bloqueio para uma origem externa de teste.

## Reexecutar a integração

Com o servidor local iniciado e o `.env.local` configurado, em PowerShell:

```powershell
$env:CORREIAI_RUN_REAL_TESTS = '1'
node scripts/validate-real-integration.mjs
```

O script exige autorização explícita por variável, aceita somente aplicação em localhost/127.0.0.1 e confere o projeto Supabase antes de criar fixtures. Não faz chamadas pagas nem aplica migrations. O resultado detalhado e a imagem de teste ficam em `git rev-parse --git-path validation`, fora dos arquivos versionados. O script deve ser executado a partir da raiz do repositório, com as dependências instaladas por `npm ci`.
